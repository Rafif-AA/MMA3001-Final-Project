Environment and required files

  1. Open the selected original notebook in Google Colab. Choose a GPU runtime for training and for the saved-weight timing cells, which specify device=0.
  2. Install the libraries used by the chosen notebook. The full set across the folder is shown below; Colab supplies its own integration modules.
  3. Mount Drive before accessing /content/drive. Provide the dataset YAML, images and labels, and the trial checkpoint for saved-weight evaluation.
  4. Update paths to match your files, then run cells in dependency order. Later analysis cells depend on model, metrics, network or df from earlier cells.

Outputs and calculations

OperationInputsOutputs / interpretation
TrainingPretrained weights, dataset YAML, epoch limit, image sizeRun directory containing best.pt, last.pt, training metrics and plots.
Saved-weight validationWEIGHTS_PATH, DATA_PATH, validation settingsLoaded YOLO model, metrics and four performance curves saved under evaluation.save_dir.
Confusion-matrix displaymetrics.confusion_matrix and model.namesRaw and column-normalised matrices. Wrinkle is hidden after normalisation; background is retained.
Activation profilingLoaded network and dummy image resolutionTable of tensor output shapes and activation counts. Counts can include repeated leaf-module invocations.
TimingValidation at 1280, batch 1, CUDA device 0Inference ms/image and the separately computed preprocessing + inference + postprocessing total.
Roofline estimateFLOPs, parameter count, activation count, reference peak/bandwidthArithmetic intensity and idealised compute ceiling. This is not a measurement of hardware throughput.

Roofline equations used in the newer notebooks

parameter_bytes = parameter_count * 4
activation_bytes = activation_count * 4 * 2
estimated_bytes = parameter_bytes + activation_bytes
arithmetic_intensity = FLOPs / estimated_bytes
ridge_point = reference_peak_FLOPs_per_second / bandwidth_bytes_per_second
ceiling = min(reference_peak, arithmetic_intensity * bandwidth)

Trials 2,5 and 4,5 estimate FLOPs for a 1280 x 1280 FP32 model copy. Trials 1,5, 3,5 and 5,5 retain fixed 640 x 640 Nano-model constants. The newer cells use a G4 reference of 117 TFLOP/s and 1597 GB/s as supplied in their source; these constants do not identify the GPU actually running the notebook.

Software tests

The documented source snapshots are covered by a separate CPU unit-test suite. See the HTML test report and scope and rerun instructions. Tests use small neural networks and controlled external-model calls; they do not establish detector accuracy or production-line performance.

Source provenance and scope

Source: MMA3001 Colab Files shared Drive folder. Each notebook page links to the original Colab file and an offline source-only snapshot. Snapshots preserve every code and markdown cell; outputs, execution counts and personal metadata were removed. The manifest records original-file and snapshot SHA-256 hashes.

This reference was produced through static parsing with Python's standard library. Source docstrings are reproduced as written; accompanying explanations describe the actual calls and variables. Models and datasets were not downloaded or executed to build these pages.
